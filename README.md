# 🧪 规则养蛊局 RULE LAB

**规则由你制定，漏洞由它们发现。**

一个基于虚拟人群模拟（Agent-Based Modeling）的现实制度压力测试平台。
制定资源分配、任务分工、奖励与惩罚规则，由数百个具有不同性格与策略的虚拟人物自主行动，
观察个体逐利行为如何涌现为群体问题，并由红队机制主动搜寻制度漏洞。

> 不依赖付费 AI API，不需要真实校园数据或用户身份信息。零 npm 依赖，一个 `node server.js` 即可启动。

## 快速开始

```bash
# 需要 Node.js >= 18（无任何 npm 依赖）
node server.js
# 打开 http://localhost:3000
```

Windows 双击 `start.bat` 同样可以启动。

## 两个实验室

### 🧺 共享资源实验室
模拟宿舍洗衣机、公共设备的预约与使用（14 天 × 24 时段，60 名住户）。
可调规则：预约开关与上限、提前预约窗口、爽约/超时惩罚、动态价格、排队规则（先到先得/抽签/积分优先）、错峰奖励、违规发现概率……

可观察的涌现问题：
- **预约囤积**：钻营者批量抢占高峰预约位，顶部 10% 住户垄断洗涤次数
- **恶意预约（幽灵占位）**：爽约惩罚过低时，预约成为霸占时段的零成本手段
- **超时占用 / 责任推诿**：超时惩罚缺失时，遵守规则的人为钻营者接盘等待
- **高峰垄断**：缺乏价格杠杆时，黄金时段被会预约的人通吃
- **排队不公**：先到先得奖励有空闲时间的人

### 👥 团队协作实验室
模拟小组作业（6 团队 × 8 人 × 5 轮项目）。
可调规则：任务分配（自主认领/组长分配/随机/竞拍）、贡献评分（自我申报/同伴互评/量化计量/混合）、奖励分配（平均/按贡献/头部奖励）、审计概率、互评人数、困难任务加分……

可观察的涌现问题：
- **自我申报刷分**：低投入高申报，诚实者反而吃亏
- **互评串通**：高钻营倾向个体形成小圈子互相打高分
- **困难任务逃避**：理性个体都挑轻活，硬骨头烂尾
- **制度诱导搭便车**：平均奖励 + 低威慑下，努力成为劣势策略
- **竞拍过度承诺**：靠夸大承诺抢任务，实际投入不足

## 核心特性

| 能力 | 说明 |
| --- | --- |
| ⚙ 规则热更新 | 实验**运行中**修改规则，立即观察群体行为拐点 |
| ⚡ 外部干预 | 中途注入设备故障、突发需求、成员退出、突击审计等突发事件 |
| 📡 实时可视化 | SSE tick 级推送：设备状态/热力图、团队面板、指标曲线、事件日志 |
| 🛡 红队机制 | 运行中实时警报 + 实验后深度扫描，漏洞关联到具体规则参数 |
| 📼 可追溯报告 | 每个漏洞附带事件级证据（tick、个体、行动），含规则修改记录 |
| 🔁 可复现 A/B | 种子化随机数，相同规则+种子结果完全一致；报告页一键"应用修复并同种子重跑"，自动对比基线 |

## 架构

```
rule-lab/
├── server.js                  # 零依赖 HTTP 服务：静态文件 + REST API + SSE 实时流
├── src/
│   ├── engine.js              # 模拟引擎：tick 循环、事件日志（seq 递增）、规则修改记录
│   ├── rng.js                 # 种子化随机数（mulberry32），保证实验可复现
│   ├── metrics.js             # 基尼系数、顶部份额、百分位、Pearson 相关等群体指标
│   ├── redteam.js             # 漏洞报告组装（健康度评分、指标口径）
│   └── scenarios/
│       ├── shared-resource.js # 场景 1：共享资源（洗衣机预约）
│       ├── team-collab.js     # 场景 2：团队协作（小组作业）
│       └── index.js           # 场景注册表
├── public/                    # 原生 SPA（无构建步骤）：index.html / style.css / app.js / charts.js
└── tests/
    ├── run-sim.js             # 无头测试：两场景 × 默认/宽松规则 + 可复现性验证
    └── e2e.js                 # HTTP 端到端：API/SSE/扫描/报告/对比/修复重跑
```

### 模拟方法
- **智能体原型**：每个个体随机分配性格参数（钻营倾向、勤奋度、耐心、风险偏好、领导力），
  分为守法者 / 机会主义者 / 钻营者 / 奉献者 / 搭便车者（团队场景另有实干者 / 刷分者 / 贡献者）。
- **决策模型**：个体根据规则带来的收益、成本与风险估算期望效用，自主选择行动
  （走步使用 / 预约 / 囤积预约 / 爽约 / 超时 / 挑轻活 / 刷分 / 串通 / 搭便车）。
- **涌现观察**：平台不预设"坏行为"，只改变规则参数，让问题（或它的消失）自己发生。

### 场景接口（扩展新实验室）
一个场景即一个模块，导出：`id / name / description / paramSchema / defaults / interventions / metricKeys`
与 `init / step / metrics / visualize / totalTicks / intervene / describe / liveCheck / detect`。
`paramSchema` 驱动前端参数面板自动渲染，`detect` 输出漏洞（触发规则 + 证据 + 影响 + 修复建议）。
详见 `src/scenarios/shared-resource.js`。

## API 速查

| POST | `/api/sims/:id/scan` | 立即运行红队扫描 |
| GET | `/api/sims/:id/report` | 漏洞报告（健康度 + 漏洞 + 证据 + 修复建议） |
| GET | `/api/sims/:id/compare?with=` | A/B 对比（缺省自动选同场景基线） |

## 黑客松演示建议（3 分钟脚本）

1. 首页点击「共享资源实验室」→ 直接运行，观察默认规则下的设备热力图与指标曲线。
2. 生成漏洞报告：展示"恶意预约/幽灵占位"卡片，展开**可追溯证据**（tick 级事件）。
3. 点击「应用修复并重跑（同种子）」→ 爽约惩罚提高后的新实验自动运行。
4. 回到报告页查看 **A/B 对比表**：爽约率、基尼系数、满意度的变化一目了然。
5. 切到团队协作实验室，把评分改成"自我申报"、审计调到 0 → 刷分膨胀实时警报响起。

## 本次更新（v2）

- 🎨 **浅色主题 + 自定义配色**：默认浅色，顶栏「🎨 主题」可切换浅色/深色、自定义主色与辅助色，选择持久化到本地。
- ✨ **自定义场景**：顶栏「新建场景」→ 描述你的制度 → 系统用本地规则引擎构思一套规则 → 逐条修改名称/单位/含义/默认值（或增删）→ 确认后运行。不再局限于两个示例。
- 🏷 **指标单位**：所有指标标注单位（%、小时、积分、分、×、人次等）。
- 💬 **规则含义说明**：每条规则参数下方直接显示含义说明 + 单位徽标，时间/费用/惩罚语义已明确：
  - 时间单位 = 1 时段 = 1 小时（一天 24 时段）
  - 费用 = 虚拟「积分」（本实验的虚拟货币，非真实金额）
  - 惩罚 = 扣虚拟积分（影响积分优先排队与满意度），非现金罚款或禁用
  - 概率类参数以 % 展示；`申报审计概率`/`搭便车判定阈值`/`低可见任务权重`/`每人每轮精力` 均已附白话解释
- 👥 **虚拟人物构成可自定义**：每人类型（守法者/机会主义者/钻营者/奉献者/搭便车者 或 实干者/平衡者/刷分者/贡献者/搭便车者）的数量可单独调节，总量自定。
- 💾 **结果保存 + 横向对比**：实验完成自动写入 `data/results.json`（也可手动「💾 保存结果」）；「结果对比」页跨多次实验横向对比指标与规则差异，支持导出/删除/清空。
- 🔁 **进度缓存 + 恢复**：规则设置与人物构成实时缓存到本地；退出实验室后再进入会提示「恢复上次进度」，基于种子确定性快进恢复到原 tick。

## 局域网与公网访问

服务器显式绑定 `0.0.0.0`（所有网卡），启动时会在控制台打印本机与局域网地址，例如：

```
本机:     http://localhost:3000
局域网:   http://10.6.90.197:3000   （同一网络的其它设备用此地址访问）
```

- **同一 WiFi/内网的其它设备**：直接访问上面打印的「局域网」地址即可（例如 `http://10.6.90.197:3000`）。
- 若其它设备仍打不开，通常是 **Windows 防火墙**拦了 Node 的入站连接：请在「高级安全 Windows Defender 防火墙 → 入站规则」新建一条放行 TCP 3000 的规则。
- **公网（互联网）访问**：本仓库不内置公网隧道。需要公网 URL 时，在能联网的机器上运行任一隧道工具即可，例如 Cloudflare 零配置隧道：
  ```bash
  cloudflared tunnel --url http://localhost:3000   # 输出一个 https://xxx.trycloudflare.com 公网地址
  # 或 npx localtunnel --port 3000
  ```

> 注：若运行环境本身无外网连接，则只能在同一局域网内访问，无法生成公网地址。
